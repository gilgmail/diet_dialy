## 🎯 可行方案建議

### 方案 A: 快速發布方案 (推薦) ⭐

**目標**: 在 4-6 週內達到可發布狀態

#### 優先級 1: 修復關鍵問題 (2 週)

1. **Mobile-Web 同步修復** 🔴 Critical
   - **問題**: iOS app 與 Web 資料不同步
   - **解決方案**:
     - 確認 Supabase client 在 mobile 正確初始化
     - 驗證 authentication flow
     - 測試 realtime subscriptions
   - **工作量**: 3-5 天
   - **影響**: 用戶體驗核心功能

2. **資料庫 Schema 對齊** 🔴 Critical
   - **問題**: `daily_symptom_entries` schema 不一致
   - **解決方案**:
     - 統一 web/mobile 的資料結構
     - 建立 migration scripts
     - 更新 TypeScript types
   - **工作量**: 2-3 天
   - **影響**: 資料完整性

3. **導航錯誤修復** 🟡 High
   - **問題**: TodayScreen 導航到 Insights 失敗
   - **狀態**: ✅ 已修復（2025-01-12）
   - **驗證**: 需要測試確認

4. **設定更新錯誤修復** 🟡 High
   - **問題**: SettingsService 更新 hero 模組時出錯
   - **狀態**: ✅ 已修復（2025-01-12）
   - **驗證**: 需要測試確認

#### 優先級 2: 核心功能完善 (2 週)

**注意**: 自訂食物建立和進階圖表分析已移至 Phase 2，Phase 1 專注核心功能

5. **離線模式基礎** 🟡 Medium（可選）
   - **方案**: 
     - 使用 AsyncStorage 暫存資料
     - 建立 sync queue 機制
     - 網路恢復時自動同步
   - **工作量**: 5-7 天
   - **價值**: 提升用戶體驗（網路不穩定時）

#### 優先級 3: 品質提升 (2 週)

6. **測試覆蓋率提升** 🟢 Medium
   - **現狀**: 10% → **目標**: 40%
   - **重點**:
     - Services 層測試（FoodDiaryService, SymptomDiaryService）
     - API routes 測試
     - 關鍵業務邏輯測試
   - **工作量**: 5-7 天
   - **價值**: 減少回歸錯誤

7. **Code Quality 改善** 🟢 Medium
   - **現狀**: 704 console statements
   - **方案**:
     - 執行 `scripts/cleanup-console-logs.sh`
     - 移除 unused exports
     - 修復 ESLint warnings
   - **工作量**: 2-3 天
   - **價值**: 生產環境準備

8. **效能優化** 🟢 Medium
    - **重點**:
      - 圖片優化（WebP, lazy loading）
      - API 回應時間優化
      - Mobile app 啟動時間優化
    - **工作量**: 3-4 天
    - **價值**: 提升用戶體驗

#### 交付成果

**4-6 週後可達成**（核心功能優先）:
- ✅ 穩定的跨平台同步（Mobile ↔ Web）
- ✅ 完整的核心功能（記錄、追蹤、同步、視覺化）

- ✅ 生產環境就緒的程式碼品質

# 食物日記 UX 改進說明

## 改進重點

### 問題描述
原先的實現可能讓使用者誤以為**必須**從資料庫選擇食物才能記錄，但實際上這是不必要的限制。

### 解決方案
明確告知使用者可以**直接輸入任何食物名稱**，搜尋只是輔助功能。

## 改進內容

### 1. AddFoodEntryScreen.tsx

**新增輔助說明文字**
```typescript
<Text style={styles.helperText}>
  可以直接輸入或從資料庫搜尋
</Text>
```

**位置**: 在「食物名稱」標籤下方
**目的**: 明確告訴使用者有兩種輸入方式

### 2. FoodSearchInput.tsx

**改進無結果訊息**

**原訊息**:
```
找不到「{value}」
請嘗試其他關鍵字或手動輸入
```

**新訊息**:
```
資料庫中沒有「{value}」
沒關係！可以直接使用此名稱記錄
```

**改進點**:
- 更正面、友善的語氣
- 明確告知可以直接使用輸入的名稱
- 減少使用者焦慮感

## 使用流程

### 情境 1: 使用資料庫食物（推薦）

1. 輸入關鍵字（例如："米"）
2. 從搜尋結果中選擇食物
3. 系統自動填入營養資訊
4. 確認並儲存

**優點**: 快速、準確，自動填入營養資訊

### 情境 2: 自訂食物名稱（同樣支援）

1. 直接輸入食物名稱（例如："媽媽做的炒飯"）
2. 看到「資料庫中沒有此食物」訊息
3. **繼續使用此名稱**，手動輸入份量、熱量（選填）
4. 儲存

**優點**: 靈活、適合家常菜或特殊食物

### 情境 3: 部分使用資料庫資訊

1. 搜尋並選擇接近的食物（例如："白米飯"）
2. 修改食物名稱為更具體的描述（例如："糙米混白米飯"）
3. 調整份量、熱量資訊
4. 儲存

**優點**: 結合資料庫參考和個人化描述

## 資料儲存

**所有情境的資料都會儲存到 Supabase `food_entries` 表**

```typescript
{
  user_id: string,          // 使用者 ID
  food_name: string,        // 食物名稱（可以是任何文字）
  meal_type: MealType,      // 餐點類型（早/午/晚/點心）
  portion_size?: string,    // 份量（選填）
  calories?: number,        // 熱量（選填）
  notes?: string,           // 備註（選填）
  consumed_at: timestamp,   // 用餐時間
}
```

## 技術實現驗證

### 輸入驗證
```typescript
if (!foodName.trim()) {
  Alert.alert('錯誤', '請輸入食物名稱')
  return
}
```

**重點**: 只驗證食物名稱不為空，**不驗證是否來自資料庫**

### 儲存邏輯
```typescript
await createEntry({
  food_name: foodName.trim(),  // 使用使用者輸入的任何文字
  meal_type: mealType,
  portion_size: portionSize.trim() || undefined,
  calories: calories ? parseInt(calories, 10) : undefined,
  notes: notes.trim() || undefined,
})
```

**重點**: 直接使用 `foodName`，不論來源

## UI 提示總結

| 位置 | 訊息 | 目的 |
|------|------|------|
| 標籤下方 | "可以直接輸入或從資料庫搜尋" | 告知兩種輸入方式 |

## 使用者體驗目標

✅ **降低認知負擔**: 使用者不需要思考"是否必須選擇資料庫食物"
✅ **增加靈活性**: 支援任何食物名稱，不限於資料庫
✅ **保留便利性**: 資料庫搜尋仍然提供快速填入功能
✅ **正面引導**: 訊息語氣友善，鼓勵使用者自由記錄

## 與 Web App 的一致性

**Mobile App**:
- 允許自由輸入任何食物名稱
- 儲存到 `food_entries` 表

**Web App**:
- 同樣允許自訂食物
- 同樣儲存到 `food_entries` 表
- 共享 `diet_daily_foods` 資料庫供搜尋參考

**資料流**:
```
使用者輸入 → food_entries (個人記錄)
           ↗
資料庫搜尋 → diet_daily_foods (共享參考資料)
```

## 後續可能改進

1. **常用食物建議**: 根據使用者歷史記錄推薦常吃的食物
2. **快速記錄**: 從歷史記錄一鍵複製
3. **智慧建議**: 根據時間推薦適合的餐點類型
4. **營養統計**: 自訂食物也能累積營養數據

## 總結

此次改進的核心理念：

> **記錄比完美更重要**

讓使用者可以快速、輕鬆地記錄飲食，而不是被資料庫限制困住。搜尋功能是**錦上添花**，不是**必要門檻**。
